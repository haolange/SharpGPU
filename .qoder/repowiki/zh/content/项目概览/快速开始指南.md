## 核心组件
- RHIInstance：创建 GPU 实例，选择后端（DirectX 12 / Vulkan），管理设备生命周期
- RHIDevice：代表一个 GPU 设备，提供命令队列、管线、缓冲、纹理等资源创建能力
- RHICommandQueue / RHICommandBuffer：提交命令、编码渲染/计算/传输通道
- RHIFunction / RHIPipeline：封装着色器函数与管线状态
- RHIBuffer / RHITexture：GPU 内存与图像资源
- 传输通道：用于缓冲/纹理之间的拷贝、重映射、查询解析等

### 后端配置与设备能力检测

**新增** SharpGPU 支持三种后端：DirectX 12、Vulkan 和 Metal。后端选择策略如下：

- Windows 默认使用 DirectX 12，可通过 `bForceVulkan` 参数强制使用 Vulkan
- macOS 和 iOS 默认使用 Metal
- Linux 和 Android 使用 Vulkan

设备能力检测通过 `RHIDevice.Capabilities` 获取，包含 14 个能力域：
- Raster（光栅化）、Binding（绑定）、Synchronization（同步）
- Memory（内存）、Storage（存储）、PipelineCache（管线缓存）
- Presentation（呈现）、RayTracing（光线追踪）、Mesh（网格着色）
- MachineLearning（机器学习）、WorkGraph（工作图）、IndirectCommandBuffer（间接命令缓冲）
- Compute（计算）、FunctionLibrary（函数库）

每个能力域都有等级（Tier）、策略（Strategy）和来源（ProbeKind）信息。

### 资源类型与管理

**新增** SharpGPU 提供两种主要 GPU 资源类型：

#### 缓冲区（Buffer）
- `RHIBufferDescriptor` 包含字节大小、元素格式、用途和存储模式
- 存储模式包括：GPULocal、HostUpload、GPUUpload、Readback、Memoryless
- 支持 Committed 和 Placed 两种分配方式

#### 纹理（Texture）
- `RHITextureDescriptor` 包含 mip 数量、范围、像素格式、采样数和维度
- 支持多种纹理维度和格式
- 视图是调用方已有资源上的一段范围加一种访问方式

#### 视图（View）
- Buffer 使用 `CreateBufferView` 创建
- Texture 使用描述 mip 与数组范围的视图描述符
- Tensor 和函数库有自己的视图类型

### 着色器与管线管理

**新增** SharpGPU 的着色器处理流程：

#### 着色器函数
- `RHIFunctionDescriptor` 指向编译后的字节码
- 支持的载荷类型：Dxil、SpirV、MslSource、MetalLibrary
- 函数库将一份载荷编译一次，再由 `CreateFunction` 选取入口

#### 管线类型
- **光栅管线**：锁定采样数、颜色与深度格式、渲染状态、可选片段函数、管线布局
- **计算管线**：锁定线程组大小、计算函数和布局
- **光线追踪管线**：专用管线类型
- **工作图管线**：专用管线类型
- **机器学习管线**：二进制管线，从 `RHIMLBinary` 转换为 `RHIMLPipeline`

#### 管线缓存
- `RHIPipelineCache` 导入和导出透明字节
- 调用方负责保存缓存数据
- 驱动或 GPU 变化会使旧条目不兼容

### 绑定表与命令编码

**新增** SharpGPU 的命令编码系统支持六种不同的通道类型：

| 通道类型 | 开始方法 | 结束方法 | 用途 |
|---------|----------|----------|------|
| 传输通道 | `BeginTransferPass` | `EndTransferPass` | 缓冲/纹理拷贝、重映射 |
| 计算通道 | `BeginComputePass` | `EndComputePass` | 计算着色器执行 |
| 光线追踪通道 | `BeginRaytracingPass` | `EndRaytracingPass` | 光线追踪渲染 |
| 光栅通道 | `BeginRasterPass` | `EndRasterPass` | 传统图形渲染 |
| 机器学习通道 | `BeginMLPass` | `EndMLPass` | 机器学习推理 |
| 工作图通道 | `BeginWorkGraphPass` | `EndWorkGraphPass` | 工作图执行 |

#### 绑定表
- `RHIPipelineLayoutDescriptor` 给出绑定表布局、Push Constant 大小
- 录制时编码器绑定 `RHIBindingTable`
- 支持有限的 bindless 范围表达

#### 屏障系统
- 每种编码器都录制 `RHIBarrier`：全局、Buffer 或 Texture
- 阶段与访问掩码成对使用 Before/After
- 纹理屏障另带 `ERHITextureLayout`（13 个值）

### 提交与同步原语

**新增** SharpGPU 的提交与同步机制：

#### 命令提交
- `RHICommandQueue.Submit` 接收 `RHIQueueSubmitDescriptor`
- 支持命令缓冲、信号量等待、信号量发出和完成栅栏
- 空提交会抛出异常，确保队列中必须有工作或同步操作

#### 同步原语
- `RHIFence`：CPU 与 GPU 之间的信号，`Wait` 返回 `ERHIFenceStatus`
- `RHISemaphore`：GPU 与 GPU 之间的信号
- `RHIQuery`：时间戳、遮挡和管线统计查询

#### 查询系统
- 支持时间戳查询、遮挡查询和管线统计查询
- 结果未就绪时 `TryGetTimestamp`、`TryGetOcclusion` 和 `TryGetPipelineStatistics` 返回 false
- 校准时间戳仅在同步能力报告可用时存在

### 交换链呈现

**新增** SharpGPU 的交换链呈现系统：

#### 交换链描述
- `RHISwapChainDescriptor` 包含窗口句柄、原生表面种类、范围、缓冲数量、格式
- 支持多种呈现模式和帧率设置
- 支持 Headless 模式用于无窗口场景

#### 呈现状态
- 获取和呈现返回 `ERHISwapChainStatus`：Success、NotReady、Timeout、Occluded、Suboptimal、OutOfDate、SurfaceLost、DeviceLost
- Suboptimal 仍可继续呈现
- OutOfDate、SurfaceLost 和 DeviceLost 需要重建交换链或设备

#### 平台支持
- Win32Hwnd、AppKitNsWindow、X11Window、WaylandSurface、UIKitUiWindow、AndroidNativeWindow、Headless

### 设备能力详解

**新增** SharpGPU 的设备能力系统提供详细的硬件能力探测：

#### 能力等级
- `ERHICapabilityTier` 从 Unavailable 到 Tier4
- 每个等级表示特定功能的支持程度
- 能力矩阵按域定义，不是统一的等级体系

#### 能力策略
- `ERHICapabilityStrategy` 说明后端如何实现：CoreApi、NativeExtension、NativeSpecialized、NativeLibrary
- `ERHICapabilityProbeKind` 说明答案是如何得到的

#### 精确查询
- `QueryFormatSupport`：格式支持查询
- `QueryResolveSupport`：解析支持查询
- `QueryRasterAttachmentSupport`：光栅附件支持查询
- 协作矩阵配置查询

## 性能注意事项
- 合理使用屏障（Barrier）减少不必要的同步开销
- 尽量复用命令缓冲与管线对象，避免频繁创建销毁
- 使用合适的存储模式（HostUpload/Readback/GPULocal）优化数据流
- 对大尺寸数据传输，优先批量拷贝与合并提交
- 启用查询（Statistics）评估吞吐瓶颈（输入装配、像素着色器调用次数等）
- 利用管线缓存加速管线创建过程
- 选择合适的通道类型以获得最佳性能

## 故障排除指南
常见问题与解决思路
- 无法找到 .NET SDK 或版本不匹配
  - 确认安装了 global.json 指定的 SDK 版本
  - 使用 dotnet --info 核对当前 SDK
- 无可用后端（DirectX 12 / Vulkan）
  - 确保显卡驱动已更新，系统具备对应 API 支持
  - 使用 IsBackendSupported 检测后再创建实例
- 原生 DLL 加载失败或路径问题
  - 检查应用部署目录下的 runtimes/win-<arch>/native 是否存在所需 DLL
  - 可通过 SharpGpuNativeLibraries.Configure 显式设置 DirectML/DirectStorage/PIX 目录（必须在首次运行时之前配置）
- 长路径导致 NativeLibrary 加载失败
  - 将应用移动到较短路径下运行，或使用修复后的包/路径策略
- 包模式与源模式混用导致解析错误
  - 保持 StackReferenceMode 一致，不要混合 ProjectReference 与 PackageReference
- 构建/测试失败
  - 参考 docs/VERIFICATION.md 中的权威命令，使用隔离缓存与明确参数重新执行
- 设备能力不足
  - 检查 RHIDevice.Capabilities 中的具体能力等级
  - 使用 QueryFormatSupport 等精确查询验证功能支持
